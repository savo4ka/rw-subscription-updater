# rw-subscription-updater

Сервис автоматически обновляет значение заголовка в правилах ответа подписки (Response Rules) панели [Remnawave](https://github.com/remnawave/panel), когда меняется файл на GitHub.

Типичный сценарий: держать в актуальном состоянии routing-deeplink для Happ из репозитория [roscomvpn-routing](https://github.com/hydraponique/roscomvpn-routing), не обновляя его в панели вручную.

## Как это работает

Каждые `CHECK_INTERVAL_SECONDS` секунд сервис выполняет следующие шаги:

1. Запрашивает настройки подписки из панели (`GET /api/subscription-settings`).
2. Находит правило с именем `RULE_NAME`, а в нём заголовок `HEADER_NAME`.
3. Загружает содержимое файла по адресу `GITHUB_URL`.
4. Если значения отличаются, записывает новое значение в панель (`PATCH /api/subscription-settings`).

Если значения совпадают, сервис ничего не делает. Ошибка на одной итерации (панель или GitHub недоступны) записывается в лог, и сервис продолжает работать.

## Требования

- Панель Remnawave и API-токен к ней.
- В панели уже есть правило ответа с нужным именем и нужный заголовок внутри него. Сервис только обновляет значение заголовка, но не создаёт правило и сам заголовок.
- Docker и Docker Compose, либо Python 3.13+ для локального запуска.

## Настройка

Скопируйте пример конфигурации и заполните его:

```bash
cp .env.example .env
```

| Переменная | Обязательная | Описание |
|---|---|---|
| `REMNAWAVE_TOKEN` | да | API-токен панели Remnawave |
| `REMNAWAVE` | да | Адрес панели, например `http://remnawave:3000` или `https://panel.example.com` |
| `RULE_NAME` | да | Имя правила ответа в настройках подписки, например `Happ` |
| `HEADER_NAME` | да | Имя заголовка внутри правила, значение которого нужно обновлять, например `routing` |
| `GITHUB_URL` | да | Ссылка на raw-файл с актуальным значением |
| `CHECK_INTERVAL_SECONDS` | нет | Интервал проверки в секундах, по умолчанию `300` |

Если панель указана по `http://` (например, при обращении по внутренней Docker-сети), сервис добавляет к запросам заголовки `X-Forwarded-Proto: https` и `X-Forwarded-For: 127.0.0.1`. Без них Remnawave отклоняет запросы, которые пришли не через reverse proxy.

## Запуск в Docker

Сервис подключается к внешней сети `remnawave-network`, которую создаёт compose-файл Remnawave. Это позволяет обращаться к панели по адресу `http://remnawave:3000` без выхода в интернет.

```bash
docker compose up -d
```

Логи:

```bash
docker compose logs -f
```

Если сеть называется иначе, поправьте её имя в [docker-compose.yaml](docker-compose.yaml).

## Локальный запуск

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python main.py
```

Переменные окружения загружаются из файла `.env` в текущей директории.

```

2026-09-26 12:00:01 [INFO] Совпадают, изменений не требуется
2026-09-26 12:05:01 [INFO] Значения отличаются, обновляю панель
2026-09-26 12:05:01 [INFO] Было: ...
2026-09-26 12:05:01 [INFO] Стало: ...
```

Если правило или заголовок не найдены, в логе появится `WARNING`, а панель не изменится.

## Остановка

По сигналу `SIGTERM` или `SIGINT` сервис дожидается конца текущей проверки и завершает работу. В `docker-compose.yaml` для этого задан `stop_grace_period: 30s`.

## Важно

Содержимое `GITHUB_URL` записывается в панель как есть, без проверки, и сразу попадает в подписки всех пользователей, к которым применяется правило. Указывайте только источник, которому доверяете.
